# 暗黑看山降临机制

暗黑看山是与知乎热榜问题关联的个人每日探索事件。“降临位置”指一个被选中的知乎热榜问题；用户先寻找这个问题，再从其对应的活动入口挑战Boss。位置随机，战斗难度和奖励仍由对战规则决定。

## 正式产品中的生成流程

1. 按北京时间划分活动日期。每天从知乎热榜取得一份问题列表，保留有效的问题链接、按问题去重，形成当天候选池，最多30题。实际有效题目数记为N；只有N大于0时才开放寻找。
2. 当天候选池固定保存，供用户共用。之后热榜名次或内容变化，不会让已经分配的位置随之移动。列表标明采集时间，用户按活动中的当天候选题单寻找。
3. 用户当天首次进入知斗或打开活动时，系统从N个问题中为其等概率抽取1题，并记录日期、用户和问题。无需在零点给所有未上线用户提前生成数据。
4. 每位用户独立抽取，每人每天恰好有1处藏身位置。其他用户的抽取结果不会占用或排除某道题，因此两人可能碰巧在同一题找到Boss；不保证每个人的位置都不同。
5. 用户点击问题条目下的“探索此提问”，系统检查它是否等于当天已保存的位置。未命中就标记为“已探索”；命中后展示问题标题及“进入Boss对战”按钮。

## 随机性的含义

| 项目 | 规则 |
|---|---|
| 随机什么 | 在当天候选问题中选择藏身位置 |
| 是否一定降临 | 有可用候选池时，每位参与用户当天都有1处位置 |
| 单个问题的初始概率 | 1/N，各题相同，不按榜单名次或热度加权 |
| 是否受资产或行为影响 | 不因钱包余额、买卖、战绩、点赞或打赏改变位置 |
| 点击探索 | 检查已经选定的位置，不再随机抽一次 |
| 重复点击与刷新 | 不换位置，不重复计算已探索进度 |
| 重新登录与挑战失败 | 当天继续使用原位置；失败只按挑战规则扣款和扣次数 |
| 第二天 | 北京时间00:00后开始新日期，重新抽取并清空寻找进度；有可能再次抽到同一问题 |

例如当天有20道候选题，每题最初被选中的概率为5%。如果已经排除5道题，Boss必在剩下15道题中；对任意一个尚未探索的问题，命中概率变为1/15，约6.67%。这是排除信息带来的变化，Boss的位置没有移动。若持续探索不同题目，最迟在第20题发现；重复点击同一题不会提高机会。

当前演示有6道内置示例题，各题初始概率约为16.67%。仅凭几次试玩或某道题连续出现，不能判断抽取不随机；随机结果允许重复。正式验证应按各候选池大小分别检查大量抽取结果及账户之间的独立性，不人为强制轮换。

## 用户会看到什么

| 状态 | 提示和操作 |
|---|---|
| 已降临但未发现 | 首页显眼提示“暗黑看山已潜入今日热榜的某个提问，去寻找它的踪迹”；不透露题目名称、排名或编号 |
| 探索未命中 | “这里没有它的踪迹”，保留已探索标记，可继续选择其他问题 |
| 探索命中 | “暗黑看山于「问题标题」下现身”，在该问题条目下解锁对战入口 |
| 战斗失败 | 保留位置与入口；当天剩余次数允许时可再次挑战 |
| 今日已击败 | 标记为已击败，关闭当天重复领奖入口 |
| 无有效题单 | 提示活动暂不可用，不虚构真实热榜或对用户扣费；其他玩法仍可体验 |

寻找免费，不扣活力币、小鱼干或挑战次数。正式开始挑战时，才检查资源、预留保证金并消耗当日挑战次数。仅打开知乎原文链接不会被当作已完成探索，也不要求用户为了找Boss去点赞、评论或打赏。

## 问题入口与演示范围

正式产品将Boss事件关联到真实知乎问题。在目前可独立实现的方案中，知斗展示热榜问题条目，探索与挑战入口就在对应条目下，原文链接供用户前往知乎阅读。若要把按钮直接嵌入知乎原生热榜或问题页，需要平台支持，属于后续接入计划。

本次桌面工具演示使用明确标注的6道示例题，链接通往知乎相关搜索，未接入实时热榜，也未在知乎原生页面插入入口。它按一份本地存档演示同样的抽取、隐藏、探索和解锁流程。正常刷新与重启不会重抽；主动重置或删除存档会清除进度，本地演示不承担正式账户的防重置限制。

正式接入时应按问题ID去重，避免同一问题重复入池而获得更高概率；空列表、接口故障和内容不可用应有明确提示。已分配的有效位置当天保持稳定；若因内容下架必须停用某题，应标明活动异常，不静默把Boss移到另一题。

实现上共用每日问题快照，每位活跃用户只生成一次位置，探索读取已有结果即可。正式账户版由服务端保存位置，发现前不把隐藏题目ID传给页面；当前单机存档可被本机用户查看，仅用于演示。
